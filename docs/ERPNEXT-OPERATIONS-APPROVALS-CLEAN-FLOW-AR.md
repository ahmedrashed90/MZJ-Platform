# إصلاح فلو NEXT ERP إلى العمليات والموافقات

## المصدر

تم التنفيذ مباشرة على النسخة المرفوعة:

`MZJ-Platform-main-activity-help-check-view-clean(1).zip`

لم يتم استخدام نسخة أقدم، ولم تتم إضافة Endpoint بديل أو Migration ترقيعية أو طبقة Patch جانبية.

## السبب الجذري

كان مسار تحديث مخزون العمليات يستخدم نفس بوابة ربط CRM. لذلك كان فشل ربط إيميل مستخدم NEXT ERP بمستخدم المنصة يمنع العمليات كلها، رغم نجاح إدخال الطلب في التراكينج.

النتيجة القديمة كانت:

1. الطلب يدخل التراكينج.
2. ربط المستخدم يفشل أو يكون ناقصًا.
3. لا تتغير السيارة إلى `under_delivery` / «مباع تحت التسليم».
4. لا تُنشأ دورة الموافقات المالية والإدارية.

## التنفيذ الصحيح بعد الإصلاح

تم فصل القرارين داخل خدمة المزامنة الأصلية:

- **العمليات:** تعتمد على أن حالة طلب NEXT ERP هي `To Deliver and Bill`، وأن نسخة الطلب غير ملغاة، وأن رقم الهيكل موجود ومطابق لسيارة واحدة في مخزون العمليات.
- **CRM:** يظل مشروطًا بربط مستخدم NEXT ERP بمستخدم فعلي داخل المنصة، لأن العميل يجب أن يُسند إلى مستخدم وفرع وقسم حقيقيين.

بالتالي، فشل ربط المستخدم لا يمنع الآن:

- ربط السيارة بالطلب.
- تحويل الحالة إلى «مباع تحت التسليم».
- تسجيل حركة العمليات.
- إنشاء أو ضمان دورة موافقات نشطة.
- ظهور السيارة في الموافقة المالية والإدارية.

## شروط عدم تغيير السيارة

لن يتم تعديل السيارة إذا:

- حالة طلب NEXT ERP ليست `To Deliver and Bill`.
- رقم الهيكل غير مرسل.
- رقم الهيكل غير موجود في مخزون العمليات.
- رقم الهيكل مكرر على أكثر من سيارة.
- نسخة الطلب ملغاة بالفعل.

في هذه الحالات تظل نتيجة التراكينج محفوظة مع تحذير واضح في استجابة الـWebhook.

## قاعدة البيانات

لا يوجد SQL جديد مطلوب لهذا الإصلاح؛ لم تتغير الجداول أو الأعمدة أو القيود.

خدمة التكامل نفسها ما زالت تستدعي تجهيز مخططات CRM والعمليات والتراكينج وتكامل NEXT ERP قبل المعالجة.
