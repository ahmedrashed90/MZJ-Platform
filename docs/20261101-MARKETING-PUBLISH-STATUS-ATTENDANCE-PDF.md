# تحسين حالات النشر وملاحظات المراجعة وتصدير حضور PDF — 2026-11-01

## التسويق

- توحيد عرض مرحلتين منفصلتين: **الاعتماد** و**حالة النشر** داخل كارت قسم النشر، شاشة مراجعة الحملة/الأجندة، والتقرير للعرض فقط.
- حالات العمل: قيد التنفيذ، قيد المراجعة، مطلوب تعديل، جاري النشر (قبل اكتمال روابط كل المنشورات)، وتم النشر (عند اكتمال كل منشورات الخطة).
- لون اعتماد هادئ وتصميم مضغوط في لوحة الألوان، بدل البادج الأخضر الكبير. الضغط على شارة الاعتماد في الكارت يفتح تفاصيل المراجعة.
- اسم منشئ الحملة أو الأجندة ظاهر في التقرير قبل الاعتماد وبعده؛ يُقرأ من اسم المنشئ المرتبط بجدول الخطط في قاعدة البيانات.
- في شاشة المراجعة يمكن كتابة نوع الملاحظة مباشرة أو اختيار نوع مقترح أو ترك النوع فارغًا، مع كتابة الملاحظة الحرة نفسها.
- لو نوع الملاحظة جديد، يحفظه السيرفر كسطر بيانات واضح أعلى الملاحظة، وتُعرض القيمة في سجل مراجعة الخطة بدون إنشاء جدول إضافي أو ترحيل قاعدة بيانات. أنواع الملاحظات الأصلية تظل تعمل بمعرّفاتها القديمة.
- لا تغيير لصلاحيات الاعتماد أو بيانات الميزانية أو سياسة تثبيت رابط المنشور.

## حضور وانصراف: تصدير PDF

- التصدير: **تقرير الحضور والانصراف - ملخص الفترة** فقط.
- ملف PDF واحد متعدد الصفحات، صفحة مستقلة لكل موظف محدد؛ عند زيادة الأيام يمكن أن تمتد بيانات الموظف نفسه إلى صفحات تالية، لكن لا تُدمج بيانات موظفين مختلفين في نفس الصفحة.
- اسم الموظف والفرع والرقم الوظيفي (عند وجوده) ظاهر في ترويسة صفحة الموظف.
- كل يوم صف واحد، ويمكنه عرض فترتي دوام وحساب ساعات العمل والفرق والتأخير كما كان.
- **تصدير Excel** يبقى بملخص وتفاصيل، بدون تعديل.

## الاختبارات

- `node scripts/test-marketing-status-and-free-review-20261101.cjs` — حالات النشر والمنشئ والملاحظات عبر 3 شاشات.
- `node scripts/test-marketing-plan-free-note-server-20261101.cjs` — حفظ الملاحظات العامة مع/بدون نوع وفئات قديمة.
- `node scripts/test-attendance-pdf-summary-only-20261101.cjs` — ملخص فقط وفصل الموظفين في صفحات مستقلة.
- PDF تجريبي من موظفين اثنين رُسم باستخدام WeasyPrint، ثم تحققنا أن المستند صفحتان منفصلتان مع أعمدة فترتي الدوام وبدون قسم تفصيلي.
- اختبارات Owners والصلاحيات المركزية وبناء TypeScript الإنتاجي لا تُعطل؛ تنفيذ بناء `pnpm run build` الكامل يحتاج حزم المشروع في بيئة تثبيت صالحة.
