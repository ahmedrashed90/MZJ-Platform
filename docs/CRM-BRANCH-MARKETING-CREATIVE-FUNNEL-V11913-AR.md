# توحيد فرع مبيعات CRM واسم الكرييتيف وميزانية Funnel — الإصدار 1.19.13

## المصدر وطريقة التنفيذ

تم تنفيذ الإصدار مباشرة على النسخة النظيفة المعتمدة **1.19.12**، داخل الملفات الأصلية ومسارات البيانات الحالية فقط. لم تُستخدم ملفات Patch جانبية، ولم تُبنَ التعديلات فوق نسخة تجريبية، ولا توجد Migration جديدة.

## أولًا: تقارير CRM وعدد «تم البيع» بعد فلتر الفرع

ظل جدول `crm.sales_transactions` هو مصدر الحقيقة الوحيد لعدد المبيعات وتاريخها وكميتها ومندوبها.

المشكلة كانت في بعض عمليات البيع القديمة التي تحتوي لقطة المندوب والقسم، لكن لقطة الفرع داخل عملية البيع فارغة. لذلك كانت العملية تدخل في إجمالي المندوب بدون فلتر، ثم تختفي عند اختيار فرعه.

تم توحيد فرع عملية البيع على الترتيب التالي، عند غياب لقطة الفرع فقط:

1. فرع العملية `crm.sales_transactions.branch_code` إن كان موجودًا.
2. الفرع الأساسي الحالي للمندوب داخل صلاحيات CRM المركزية `core.user_system_branches`.
3. فرع العميل المرتبط بالعملية كحل أخير.

نفس الفرع الفعلي يُستخدم الآن في العرض، ونطاق الصلاحيات، وفلتر الفرع، والبحث، وتفاصيل تقرير عملاء المندوب. أقسام الجملة تظل بلا فرع حسب منطقها الحالي. لم تتم إضافة طلبات ERP أو `crm.leads.sold_quantity` كمصدر بيع موازٍ.

## ثانيًا: اسم الكرييتيف في إنشاء الحملة

داخل الخطوة 2 **الكرييتيف**:

- يظهر حقل **اسم الكرييتيف** بعد اختيار النوع.
- الاسم إلزامي للحملات وبحد أقصى 160 حرفًا.
- أزيل حقل **العدد** من كرييتيفات الحملات، وتُحفظ كل وحدة كرييتيف كسجل واحد بكمية 1.
- منطق العدد في الأجندة لم يتغير.

يُحفظ الاسم في الحقل المركزي الموجود أصلًا `marketing.creatives.name`، ويُستخدم تلقائيًا في:

- الخطوة 3 الميزانية.
- الخطوة 4 جدول النشر.
- المراجعة قبل إنشاء الحملة.
- شيت العلاقات وفولدرات الخام.
- قاعدة بيانات التسويق ونافذة **تعديل الكرييتيف**.
- داش بورد التسويق في `TASK - المطلوب` و`جاهزية المطلوب`.
- صفحة **تجهيز النشر**.
- صفحة **تفاعل النشر**.

بالنسبة للحملات الموجودة بالفعل، تغيير الاسم يعدّل نفس سجل الكرييتيف ولا ينشئ كرييتيفًا أو حملة جديدة. تعديل الاسم فقط لا يعيد إنشاء التاسكات، ولا يقسم بند ميزانية مشتركًا، ولا يعيد بناء جدول النشر.

## ثالثًا: إجمالي الميزانية حسب بند Funnel

تمت إزالة ضرب قيمة بند الميزانية في عدد الكرييتيفات المرتبطة به. بند الميزانية يُحسب مرة واحدة فقط، وإجماليه هو مجموع القيم المسجلة داخله، حتى إذا كان مرتبطًا بأكثر من كرييتيف.

تم توحيد نفس الحسبة في:

- إنشاء الحملة.
- تعديل كرييتيف داخل حملة موجودة.
- عرض قاعدة بيانات التسويق.
- إجماليات Funnel.
- إجمالي الميزانية الكامل.
- تقرير PDF.

وبذلك لا يتحول بند قيمته 12,000 إلى 48,000 بسبب ربطه بأربعة كرييتيفات.

## رابعًا: إضافة Funnel جديد من الميزانية

أضيف خيار **إضافة Funnel جديد** بجوار اختيار Funnel في:

- إنشاء الحملة.
- إضافة أو تعديل كرييتيف داخل حملة موجودة.

يتم الحفظ في جدول `marketing.funnels` الحالي عبر نفس API المركزي. الاسم إلزامي، بحد أقصى 100 حرف، ويُعاد تفعيل الاسم الموجود بدل إنشاء نسخة مكررة. تتطلب العملية صلاحية إنشاء حملة أو تعديل حملة.

## حماية الفلو الحالي

- لا تغيير في حالات التاسكات أو الاعتمادات أو نسب التقدم.
- لا تغيير في Task Template أو قواعد بدء التنفيذ.
- لا تغيير في الأجندة خارج بقاء منطق العدد الحالي.
- لا تغيير في النشر أو الأرشفة أو التكاملات الخارجية.
- لا تغيير في معادلات CRM الأخرى.
- لا توجد Migration أو SQL يدوي مطلوب.
