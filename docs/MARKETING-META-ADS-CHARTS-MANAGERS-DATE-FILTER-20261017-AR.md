# تسليم تطوير حملات Meta الممولة — 17 أكتوبر 2026

## نطاق التغيير
- إضافة ثلاثة رسوم بيانية مباشرة **أسفل كروت الملخص** في تبويب **حملات Meta الممولة**: تكلفة الليد للحملة، عدد الليدات للحملة، وتفاعلات الحملة.
- كل رسم يعرض **اسم الحملة ومدير الحملة**. تظهر الأسماء الكاملة عند تمرير المؤشر، والمحور يعرض الاسم المختصر عند الحاجة.
- إضافة حقل **اسم مدير الحملة** داخل تفاصيل كل حملة، مع زر «حفظ الاسم» ورسائل نجاح/فشل. ينعكس الاسم على الرسوم والتصفية فور حفظه.
- إضافة تاريخ **من/إلى** مع حماية من النطاقات الناقصة وغير الصحيحة، مع الإبقاء على فلاتر الفترات السابقة. الفترة المخصصة تُرسل إلى Meta Insights عبر `time_range`، وتُطبَّق على كروت الملخص والرسوم والتفاصيل في استعلام واحد.
- الإحصاءات مأخوذة من حساب Meta Ads المربوط ولا تستخدم بيانات عملاء CRM. عدم توفر رقم ليد أو تفاعل يظل «—»، وليس صفرًا مفترضًا.
- أسماء مديري الحملات بيانات **محلية للمنصة**، ولا يعدّل النظام أي حملة داخل Meta.

## حفظ البيانات وأمانها
- جدول جديد `marketing.meta_ads_campaign_managers`، مفتاحه الفريد `(account_id, campaign_id)`؛ الاسم بحد أقصى 120 حرفًا.
- سجل المستخدم الذي عدّل الاسم (`updated_by`) ووقت التعديل (`updated_at`).
- ترقية قاعدة التسويق من الإصدار 1 إلى 2 بإضافة الجدول فقط؛ لا إعادة تهيئة لجداول التسويق الكبيرة أو تعديل بيانات CRM/العمليات.
- حفظ الاسم يتطلب عرض تفاعل التسويق + صلاحية تحديث التفاعل أو تعديل الحملات، ويتحقق من صلاحية التوكن والحساب الإعلاني وملكية الحملة في Meta قبل عملية الحفظ.
- `META_ADS_ACCESS_TOKEN` و`META_AD_ACCOUNT_IDS` كما في الإصدار السابق؛ لا حاجة لمتغير جديد.

## التغييرات في السورس
- `src/marketing/components/MetaAdsPanel.tsx`: الرسم والفلترة وإدارة اسم مدير الحملة.

- `server/_marketing-meta-ads.ts`: نطاق التاريخ، استرجاع الأسماء، والتحقق والحفظ الآمن.

- `scripts/check-marketing-workflow-v2.cjs`: فحص رقم إصدار تهيئة التسويق الجديد.
- `scripts/test-marketing-meta-ads-charts-manager-20261017.mjs`: 20 فحصًا لنطاق التاريخ والحفظ والملكية والرسوم.
- `package.json`: تشغيل الاختبار الجديد ضمن سلسلة typecheck المعتادة.

## التحقق
- نجحت اختبارات المصدر الموجودة حتى مرحلة تنفيذ `tsc -b`.
- اجتاز الاختبار الجديد 20/20، واختبار التكامل السابق 8/8.
- الترجمة المنفردة لملفات TypeScript/TSX المُعدلة اجتازت فحوص التكوين الأساسية.
- **لم يُختبر بناء Vercel الكامل هنا** لأن حزم React/Recharts/Postgres/أنواع Node غير موجودة في بيئة التشغيل، والاتصال بمستودع npm غير متاح. يلزم تشغيل `pnpm install --frozen-lockfile` ثم `pnpm run build` قبل نشر النسخة على Production.
- لم يتم إجراء ترحيل على قاعدة البيانات الحية أو تغيير أي بيانات Meta الفعلية.

## بعد النشر
1. تأكد من متغيرات `META_ADS_ACCESS_TOKEN` و`META_AD_ACCOUNT_IDS` الموجودة سابقًا في Vercel.
2. نفّذ نشرًا على Preview أولًا. عند أول طلب تسويق عادي بعد النشر تجري ترقية قاعدة التسويق الصغيرة لإضافة جدول اسم المدير، مرة واحدة فقط مع قفل تسلسلي.
3. افتح «تفاعل النشر ← حملات Meta الممولة»، واختر فترة مخصصة، ثم افتح حملة واكتب اسم المدير واضغط «حفظ الاسم».
4. جرّب تحديث الصفحة وتغيير التاريخ: يجب أن يظل الاسم محفوظًا وتظهر الأرقام حسب الفترة الجديدة.
