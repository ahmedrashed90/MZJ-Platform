# إصلاح أقسام التسويق وقوالب الأدوار — v1.19.9

## المصدر

تم تنفيذ النسخة من السورس النظيف المعتمد `MZJ-v1.19.7-NEXT-ERP-CLEAN-FULL(1)(4).zip` مباشرة، وليس من نسخة v1.19.8 المعدلة.

## إصلاح خطأ أقسام التسويق

تم علاج خطأ PostgreSQL:

`duplicate key value violates unique constraint "departments_name_key"`

من الجذر عبر الآتي:

- إزالة قيد الاسم العالمي القديم من `core.departments`؛ لأن اسم القسم يجب أن يكون مقيدًا داخل النظام وليس عبر كل أنظمة المنصة.
- إصلاح تلقائي وآمن لأقسام التسويق القديمة التي تحمل الاسم نفسه بمعرّفات مختلفة.
- اختيار UUID مركزي واحد للقسم ونقل عضويات المستخدمين ومراجع الحملات والأجندة والتاسكات إليه.
- الحفاظ على علامة القسم الأساسي للمستخدم عند نقل العضوية.
- عدم تغيير أي دور أو `role_id` أثناء إصلاح الأقسام.
- منع تحميل صفحة إعدادات التسويق من الفشل عند وجود تعارض قديم في الاسم.
- عند إدخال اسم قسم تسويق موجود، يعاد استخدام القسم الموجود بدل إنشاء سجل مكرر.
- عند محاولة تعديل قسم إلى اسم قسم تسويق آخر موجود، تظهر رسالة عربية واضحة بدل خطأ قاعدة البيانات الخام.

## إصلاح قوالب الأدوار المكررة

- شاشة **قوالب الأدوار** تعرض صفًا واحدًا فقط لكل اسم دور موحد.
- يتم اختيار الدور المركزي ذي الأولوية من السجلات المتشابهة للعرض والتعديل.
- لا توجد Migration لدمج أو حذف الأدوار.
- لم يتم تعديل `role_id` أو أكواد الأدوار أو صلاحياتها المخزنة.
- المستخدمون المرتبطون بالأدوار القديمة يظلون محفوظين، ويظهر إجماليهم في الصف الموحد.
