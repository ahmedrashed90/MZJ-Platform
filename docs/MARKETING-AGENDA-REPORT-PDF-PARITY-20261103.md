# تقرير الأجندة — مطابقة بيانات شاشة التقرير مع تصدير PDF

## التغيير

- إضافة بيانات الاعتماد (المراجع وتاريخ ووقت الاعتماد) إلى **التقرير المعروض** للأجندة فقط، باستخدام نفس صياغة التصدير وبتوقيت الرياض، بدون إعادة تسمية أي حقل موجود.
- الإبقاء على حقلَي «تاريخ نشر الأجندة من» و«تاريخ نشر الأجندة إلى» وإضافة «المدة» محسوبة بالأيام مع شمول يوم البداية والنهاية.
- عرض «المنصات وعدد المنشورات» من قائمة منصات النظام بالكامل، بما فيها المنصات ذات صفر منشورات، مع إبقاء المنصات التاريخية التي أوقفت لاحقًا.
- عرض «المطلوبات المختلفة» متضمنة نوع المحتوى (صورة/فيديو) و«الأفكار المختلفة» بدون تكرار، وبنفس حسابات تصدير PDF.
- استخدام مصدر بيانات مشترك لشاشة التقرير ونسخة PDF لتجنب تعارض الأرقام والعناوين عند تطويرهما مستقبلًا.
- **عدم تغيير** أي من المسميات الموجودة مسبقًا، أو تفاصيل النشر حسب المنصة ونوع المنشور، أو كروت الحملة، أو مسار الحفظ والاعتماد.
- دعم الأجندات القديمة التي لا تتضمن حقول فترة نشر مستقلة باستخدام أقدم وآخر موعد منشور كما في PDF.

## الملفات المعدلة

- `src/marketing/workflow/PlanReport.tsx`: حقول العرض للأجندة فقط.
- `src/marketing/workflow/campaignOverview.tsx`: ملخص الأجندة المشترك بين الشاشة وPDF.
- `src/marketing/workflow/campaignPdfExport.ts`: إعادة استخدام الملخص المشترك وتنسيق الاعتماد وتواريخ الأجندة.
- `src/marketing/workflow/workflow.css`: تنسيق جدول المنصات الجديد داخل ملخص الأجندة.
- `scripts/test-marketing-agenda-report-visible-parity-20261103.cjs`: اختبارات المطابقة وعدم تغيير جدول التفاصيل.
- `package.json`: تشغيل الاختبارات الجديدة ضمن سلسلة فحص البناء الحالية.
