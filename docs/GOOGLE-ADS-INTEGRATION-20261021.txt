MZJ Platform - Google Ads OAuth, publishing and unified paid campaigns
Release date: 2026-10-21
Source: MZJ-Platform-ATTENDANCE-EXCEPTIONAL-PERMISSIONS-CLEAN-FULL-20261020(1).zip

PURPOSE
- Extend the existing platform, never replace the YouTube or Meta connection.
- Use the SAME Google email as YouTube at the Google consent screen.
- Use a dedicated Google Ads OAuth client in the existing approved Explorer Google Cloud project.
- Select both accessible Google Ads customers (or a subset) in Marketing -> Connections.
- Inside Marketing -> Engagement -> Paid Campaigns, show Meta and Google in ONE dashboard, filter All / Meta / Google.
- Read Google campaigns, spend, impressions, clicks, CTR, lead conversions, CPL, budgets and ad summaries per customer.
- Create complete Google Search campaigns with PAUSED status and activate only after a second explicit confirmation.
- Protect Google credentials and tokens on the server, encrypted in PostgreSQL.

STEP 3 - DATABASE SCHEMA
Marketing legacy schema version 2 upgrades automatically to version 3 on the first ordinary marketing API request, using an advisory lock and a narrow transaction that only extends four provider check constraints.
A standalone idempotent SQL migration is also included:
  database/migrations/20261021_marketing_google_ads_oauth.sql
Do not run both manually unless required by deployment procedures. The upgrade does NOT clear or alter existing YouTube/Meta tokens, rows or campaign reports.

STEP 4 - CONNECT WITH THE SAME GOOGLE ACCOUNT
In Marketing -> Connections, find the Google Ads card and press Connect.
At the Google consent screen SELECT the SAME email used to link YouTube (even though its OAuth credentials are intentionally separate to avoid breaking YouTube).
After consent the system discovers accessible customer accounts; both accounts will be selectable by customer ID.
Select the desired accounts, click Save selected accounts. The Google Ads connection shows the signed-in email and existing YouTube channel status as context.
If an account does not appear, verify the Google email has suitable Google Ads permissions. If using an MCC manager, choose the child advertising accounts, not the manager itself.

STEP 5 - MANAGE AND VIEW
Marketing -> Engagement -> Paid Campaigns (Meta + Google):
  All platforms = existing Meta Ads panel + new Google Ads panel
  Meta = original Meta Ads panel, no changes to its reports or token logic
  Google Ads = only Google accounts and campaign results
Google account/campaign status/date filters are independent of the Meta filters.
Campaigns can be paused. Enabling campaigns requires marketing.campaign.edit permission and an explicit confirmation that this may cause actual spend.
Creating a Google Search campaign requires marketing.campaign.create permission. Campaign + daily budget + Saudi location targeting + ad group + phrase keywords + responsive text ad are validated and created atomically, with the campaign PAUSED.
Existing non-Search campaigns may be shown and reported, subject to Google Ads API fields and account permissions; creating them inside MZJ is not included in this release.

DATA ACCURACY AND SECURITY
- Google lead figures are based on Google Ads conversion-action categories. They are NOT CRM customer records; this release does NOT implement Google Lead Form webhooks or CRM ingestion.
- Never add Meta and Google spend across different currencies. The UI keeps amounts by advertising account/currency.
- Read-only report requests never activate campaigns or cause ad spend.
- Google OAuth refresh tokens are stored encrypted server-side; existing YouTube tokens are left intact.
- If External OAuth consent remains in Testing status, Google may expire refresh tokens after 7 days; complete verification/publishing steps for durable production authorization when eligible.
- Google Ads Explorer level has production access with daily request limits and possible feature restrictions.
- API version: v26. Paging uses Google Ads fixed 10,000-row pages without an unsupported pageSize argument.
- Important: Search campaign creation and monitoring were mocked/tested without actual production API access. Run acceptance checks on your own accounts AFTER deploying with real OAuth credentials. Do not enable a real campaign until creatives, targeting, bidding, billing and tracking are reviewed.
