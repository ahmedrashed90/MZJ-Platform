# نقل الحملة والأجندة كبداية جديدة

هذه الأداة تنقل **بيانات إنشاء الحملة والأجندة فقط** إلى النظام الجديد، ثم تستخدم نفس مولد التاسكات الأصلي داخل النظام لإنشاء جميع التاسكات من البداية.

## ما الذي يتم نقله؟

- بيانات الحملة والأجندة الأساسية.
- الكرييتيفات وملاحظات كل كرييتيف.
- كتّاب المحتوى والأقسام واليوزرات التنفيذية.
- المواعيد والسيارات والمنصات.
- الميزانية وجدول النشر الخاص بالحملة.

## ما الذي لا يتم نقله؟

- أي Task Template مرفوع سابقًا.
- الاعتمادات أو الرفض أو طلبات التعديل السابقة.
- حالات الاستلام أو نسب التقدم.
- الملفات النهائية القديمة.
- الإشعارات أو سجل تنفيذ التاسكات القديمة.


## ربط يوزرات النظام القديم بالنظام الجديد

ملف النقل يحتوي خريطة ربط صريحة بين اسم اليوزر القديم وبريد اليوزر المقابل في النظام الجديد. البريد القديم لا يُستخدم لتعيين التاسكات.

- عبدالله حسن → `abdullah.kh@mzj-platform.com`
- محمود فؤاد → `mahmoud@mzj-platform.com`
- بلال فتحي → `belal@mzj-platform.com`
- احمد ناجي → `nagy@mzj-platform.com`

قبل الإنشاء يتحقق النظام من وجود البريد الجديد ومن تطابق الاسم العربي. إذا لم يوجد اليوزر أو كان الاسم غير مطابق تتوقف العملية بالكامل ولا يتم إنشاء أي حملة أو أجندة.

## طريقة الاستخدام

1. افتح نظام التسويق.
2. افتح صفحة **قاعدة بيانات التسويق**.
3. اضغط **نقل حملة وأجندة**.
4. ارفع ملف `mzj-marketing-fresh-import-2026-08.json` الموجود داخل مجلد `migration-packages`.
5. راجع نتيجة المطابقة. لن يسمح النظام بالإنشاء إذا كان هناك يوزر أو قسم أو نوع كرييتيف أو منصة أو سيارة غير موجودة في النظام الجديد.
6. اضغط **إنشاء الحملة والأجندة والتاسكات من البداية**.

## النتيجة المتوقعة لهذا الملف

- حملة واحدة.
- أجندة واحدة.
- 20 كرييتيف.
- 26 تاسك `Task Template - قسم المحتوى` جديدة.
- 37 تاسك تنفيذ جديدة.

كل Task Template يبدأ بدون محتوى مرفوع، وكل تاسك تنفيذ يبدأ منتظرًا اعتماد Task Template المرتبط به، بنفس الفلو الطبيعي للنظام الجديد.

## الحماية من التكرار

الملف يحتوي `migrationKey` ثابتًا. عند نجاح النقل، يسجل النظام المفتاح داخل `marketing.data_migrations`. إعادة رفع نفس الملف لا تنشئ نسخة أخرى من الحملة أو الأجندة أو التاسكات.
