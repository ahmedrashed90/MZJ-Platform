# إعادة بناء تعديلات التسويق من السورس النظيف — v1.21.0

## مصدر التنفيذ

تم التنفيذ مباشرة على السورس النظيف:

`MZJ-v1.20.0-MARKETING-CONTENT-USERS-CLEAN-FULL`

لم تُستخدم أي نسخة من v1.20.1 إلى v1.20.8 كأساس أو كمصدر لنسخ الملفات.

## التعديلات المنفذة

### إنشاء الحملة

- إعادة تنظيم خطوة الميزانية من داخل المكوّن الأصلي.
- الحفاظ على نفس نموذج بيانات الميزانية والحفظ والـAPI.
- تنظيم Funnel والكرييتيف وعدد الإعلانات والأهداف والمنصات وقيمها وإجمالي البند والإجمالي الكلي.
- إعادة تنظيم جدول النشر حول فترة النشر والأيام والمنشورات والكرييتيف والمنصات وأنواع النشر.
- الحفاظ على نفس Payload إنشاء الحملة.

### إنشاء الأجندة

- إعادة تنظيم جدول الأيام والربط.
- محرر يوم واسع يعرض الكرييتيفات والأقسام واليوزرات والمنصات في مساحة مناسبة.
- إضافة الكرييتيف لليوم من لوحة واضحة.
- اختيار السيارات في نافذة مستقلة واسعة مع البحث والاختيار المتعدد.
- الحفاظ على نفس Payload إنشاء الأجندة والفولدرات وشيت العلاقات.

### الداش بورد

- عند وصول الحملة أو الأجندة إلى 100% يظهر زر «نقل إلى قسم النشر» للمستخدم الذي يملك الصلاحية الحالية `marketing.publish_prep.manage`.
- النقل يدوي فقط، وليس تلقائيًا.
- بعد النقل تختفي الحملة أو الأجندة من «جاهزية المطلوب» وتظهر في «قسم النشر» بدون تكرار.
- الـBackend يمنع النقل قبل 100% ويحافظ على حالة `publishing` عند إعادة حساب التقدم.

### إدارة الباقات

- إضافة حقل «المبيعات» إلى إنشاء وتعديل الباقة.
- نقل التصنيفات وأنواع المبيعات إلى إعدادات سيستم التسويق كمصادر قابلة للإضافة والتعديل والحذف والترتيب.
- تخزين الباقة بمعرّف التصنيف الحقيقي ومعرّف نوع المبيعات الحقيقي.
- تصدير PDF يطبع الباقات المعروضة فقط، وليس صفحة المنصة أو القائمة الجانبية.
- تجهيز جداول الإعدادات والأعمدة الجديدة تلقائيًا من `ensureMarketingSchema()`؛ لا يوجد ملف SQL يدوي مطلوب.

## حدود التعديل

- لم يتم تغيير الأدوار أو `role_id`.
- لم يتم تغيير تسجيل الدخول أو صلاحيات الأنظمة الأخرى.
- لم يتم تغيير منطق إنشاء الحملة أو الأجندة خارج المطلوب.
- لم يتم استخدام ملفات Override أو Patch جانبية.
