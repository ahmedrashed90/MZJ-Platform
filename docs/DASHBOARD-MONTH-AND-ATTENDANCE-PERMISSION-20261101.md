# إصلاح الداش بورد الشهرية وصلاحية تصحيح الحضور — 2026-11-01

## نطاق التنفيذ
- المصدر الأساسي: MZJ-Attendance-AutoCheckin-Edit-Full.zip.
- الداش بورد الرئيسية `/`: إجمالي العملاء الفريدين، المحادثات المفتوحة، «لم يتم الرد»، المناديب، توزيع الأقسام، وأرقام CRM في ملخص الإدارات من العملاء الذين سُجلوا بتاريخ واقع داخل الشهر أو الفترة المختارة (بتوقيت الرياض). لا تغيير لقواعد CRM الداخلية أو البيانات التاريخية.
- «تم البيع» يعتمد تاريخ `crm.sales_transactions.sale_at` داخل الفترة حسب توقيت الرياض، بغض النظر عن تاريخ إنشاء العميل، مع استبعاد المبيعات الملغاة وحفظ صلاحيات النطاق.
- الملخص التسويقي والتراكينج يستخدمان بالفعل التاريخ المختار؛ مؤشرات المخزون والحالات التشغيلية اللحظية تظل لحظية كما كانت.
- تفاصيل كروت العملاء تسير وفق المجموعة الشهرية نفسها؛ تفاصيل المبيعات تستدعي عمليات بيع الفترة حتى للعملاء المسجلين قديمًا.
- الحضور: تفويض صريح `attendance.records.correct` للمسؤول المختار، ويتطلب أيضًا `platform.superadmin`. هذا ليس تجاوزًا تلقائيًا لأي Superadmin. تحقق مزدوج داخل المعاملة وإبقاء سجل التصحيح الأصلي.

## تطبيق صلاحية التصحيح على قاعدة البيانات

بعد نشر السورس، **نفّذ ملف SQL المرفق مرة واحدة** باستخدام أداة إدارة PostgreSQL المصرح لها:

`database/migrations/20261101_attendance_correction_direct_grant.sql`

الملف يختار فقط الحساب النشط صاحب البريد المحدد فيه (إذا كان فريدًا)، ويضيف `allow` مباشرًا عند عدم وجود Override سابق؛ لا ينشئ صلاحية لكل الأدوار، ويسجل الإضافة في سجل تعديل الصلاحيات. لا يحتاج تحديث بيانات العملاء، ولا يغير سجلات الحضور السابقة. إذا وجد منع صريح للصلاحية فلن يتم تجاوزه تلقائيًا، ويجب مراجعته من مدير الصلاحيات.

للتأكد: افتح تقارير الحضور بالحساب المصرح له وتحقق من ظهور زر «تصحيح». الدخول بحساب مدير نظام آخر لا يملك المنح المباشر لا يُظهر الزر ولا يسمح بتنفيذ التصحيح عبر API.
