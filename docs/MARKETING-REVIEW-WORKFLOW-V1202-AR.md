# تحسين مراجعة واعتماد Task Template — v1.20.2

## المصدر

تم التنفيذ مباشرة على سورس `v1.20.1` المرفق، داخل المكونات ومسارات الـAPI الأصلية، بدون Patch منفصل أو طبقة توافق جانبية.

## ما تم تنفيذه

### شاشة المراجعة والاعتماد

- الضغط مرة واحدة على أي حقل يحدده للمراجعة ويحوّل بطاقته إلى اللون الأصفر.
- الضغط مرتين على الحقل يفتح مساحة ملاحظة مرتبطة بالحقل نفسه داخل الشاشة.
- تم إلغاء الاعتماد على نافذة المتصفح `prompt`.
- الملاحظة العامة وملاحظات الحقول تحفظ في الحقل الحالي `admin_note` بصيغة منظمة، بدون إضافة جدول أو Migration.
- الملاحظات النصية القديمة تظل مقروءة ومتوافقة.
- بعد «طلب تعديل»، يرى المستخدم الحقول المحددة باللون الأصفر وملاحظة كل حقل والملاحظة العامة.
- بعد إعادة رفع القالب تظل الملاحظات ظاهرة للمراجعة حتى الاعتماد.
- عند الاعتماد يتم مسح ملاحظات التعديل النشطة حتى لا تظهر بعد اعتماد القالب.
- سجل المراجعات يعرض نصًا مفهومًا بدل إظهار JSON الخام.

### أزرار المراجعة

تم إعادة تصميم:
- طلب تعديل.
- حفظ تعديل المراجع.
- رفض.
- اعتماد التعليمات.

وأصبحت داخل شريط إجراءات ثابت وواضح، مع تمييز بصري مستقل لكل إجراء ودعم الشاشات الصغيرة.

### الداش بورد

- `TASK - المطلوب` أصبح يجمع التاسكات حسب القسم مع فتح وإغلاق كل قسم.
- `جاهزية المطلوب` تجمع التاسكات حسب الحملة/الأجندة ثم حسب القسم.
- كارت التاسك يعرض الحالة، الكرييتيف، كود الحملة، النسبة، المسؤول، كاتب المحتوى، القسم، وزر التفاصيل.
- فلو «تم الاستلام» لم يتغير: التاسك يخرج من `TASK - المطلوب` ويدخل `جاهزية المطلوب` اعتمادًا على `received_at`.
- لم يتم إنشاء نسخة إضافية من التاسك ولم يتغير أي Status أو API لهذا الانتقال.

## قاعدة البيانات

لا توجد Migration أو ملفات SQL مطلوبة. استخدم التنفيذ حقل `marketing.task_templates.admin_note` الموجود بالفعل لتخزين بيانات المراجعة المنظمة.

## الصلاحيات

لم تتغير مفاتيح الصلاحيات. تمت إضافة قراءة `canViewFeedback` للمستخدم المكلّف بالتاسك أو صاحب صلاحية مشاهدة ملاحظات Task Template، حتى تظهر له ملاحظات التعديل الخاصة بتكليفه فقط.
